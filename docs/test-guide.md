# MaixCAM 测试步骤

测试完成后，将结果填写到 [`test-record.md`](test-record.md)。测试照片和日志先保存在本地，不必全部上传仓库。

## 1. 准备

1. 记录 MaixCAM Pro 的系统或 MaixPy 版本。
2. 确认摄像头、屏幕和 `/dev/ttyS0` 串口接线正常。
3. 在项目根目录执行 `maixtool release`，确认 `dist` 中生成安装包。
4. 安装应用并启动，确认没有模型文件找不到的报错。
5. 准备电脑串口工具或逻辑分析仪，串口参数设置为 `115200 8N1`。

## 2. 基本功能

依次测试以下项目，每项至少操作 3 次：

1. 点击 `Red`、`Blue`，确认按钮选中状态和目标颜色同步改变。
2. 点击 `Strategy`，确认界面在 `N` 和 `P` 之间切换。
3. 点击 `OSD`，确认检测框、类别和状态信息能够显示和关闭；FPS 不在画面上叠加。
4. 分别让红、黄、黑、蓝目标以及红、蓝安全区进入画面，记录实际识别类别。
5. 向 MaixCAM 发送 `0xDD`，确认程序检查抓取区域，并输出 `0x33`、`0x44` 或 `0x55` 状态。
6. 在安全区模式下发送 `0xCC`，确认程序恢复寻找本方目标。
7. 检查输出帧长度为 11 字节，帧头为 `AA BB`，帧尾为 `CC`。

## 3. 推理时间与实际运行 FPS

这两个指标需要分开测量，不能直接用主循环中的 `time.fps()` 代替：

1. 视觉推理流水线使用正式部署的 `dual_buff=True`，预热后用 `time.ticks_us()` 统计连续 300 次 `detector.detect()` 调用；不初始化显示器，不绘图，不运行 UART 和目标决策。
2. 实际运行 FPS 同样保持正式程序的 `dual_buff=True`，按固定时间窗口计算“完整循环数 / 窗口时长”；统计范围包含取图、推理、目标决策、UART、按钮绘制和 `dis.show()`。
3. 实际运行测试应安装为 Maix 应用后脱机执行，不在 MaixVision 调试运行模式下测量。
4. 预热 30 秒，随后按比赛单轮运行时间连续统计 180 秒；每 10 秒输出一次，不要逐帧打印，也不要在画面上叠加 FPS。
5. 分别记录视觉推理流水线耗时的 mean、median、P95、min、max，以及 18 个实际运行 FPS 窗口的 mean、min、max。若有 `dual_buff=False` 对照值，单独备注，不作为部署主指标。
6. 两个测试应用都会在统计结束后初始化或更新屏幕显示最终结果；测试期间不显示统计数字。

## 4. 连续运行

1. 保持摄像头画面内存在至少一个可识别目标。
2. 连续运行 10 分钟，中途各切换一次队伍颜色、策略和 OSD。
3. 记录是否出现退出、卡死、花屏、模型停止输出或串口停止发送。
4. 若出现问题，记录发生时间和当时的模式，不写成“通过”。

## 5. 历史视频回放

1. 在另一块屏幕全屏播放历史调试视频，关闭播放器控件和字幕。
2. 保持 MaixCAM 与屏幕正对，避免摩尔纹和反光。
3. 对六个类别分别记录“正确”“错误”或“未覆盖”。
4. 同一类别连续出现多帧只算一个测试片段，不以帧数计算准确率。
5. 结果只能写成“历史视频回放测试”，不能写成比赛现场准确率。

## 6. 建议保留的证据

- 应用正常启动的一张照片；
- 六类目标中实际完成测试的检测截图；
- 一段包含 FPS 输出的控制台日志；
- 一段 10 分钟连续运行的起止时间记录；
- 一组完整 UART 帧的十六进制输出。
