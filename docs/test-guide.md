# MaixCAM 测试步骤

测试完成后，将结果填写到 [`test-record.md`](test-record.md)。测试照片和日志先保存在本地，不必全部上传仓库。

## 1. 准备

1. 记录 MaixCAM Pro 的系统或 MaixPy 版本。
2. 确认摄像头、屏幕和 `/dev/ttyS0` 串口接线正常。
3. 在项目根目录执行 `maixtool release`，确认 `dist` 中生成安装包。
4. 安装应用并启动，确认没有模型文件找不到的报错。
5. 准备电脑串口工具或逻辑分析仪，串口参数设置为 `115200 8N1`。

## 2. 基本功能

依次测试以下项目，每项至少操作 3 次：

1. 点击 `Red`、`Blue`，确认按钮选中状态和目标颜色同步改变。
2. 点击 `Strategy`，确认界面在 `N` 和 `P` 之间切换。
3. 点击 `OSD`，确认检测框、类别、状态和 FPS 信息能够显示和关闭。
4. 分别让红、黄、黑、蓝目标以及红、蓝安全区进入画面，记录实际识别类别。
5. 向 MaixCAM 发送 `0xDD`，确认程序检查抓取区域，并输出 `0x33`、`0x44` 或 `0x55` 状态。
6. 在安全区模式下发送 `0xCC`，确认程序恢复寻找本方目标。
7. 检查输出帧长度为 11 字节，帧头为 `AA BB`，帧尾为 `CC`。

## 3. FPS

当前程序只有打开 OSD 时才在屏幕显示 FPS。建议使用 MaixVision 控制台采样，避免把额外绘制计入 OSD 关闭结果：

1. 在 `main.py` 主循环末尾临时启用这一行：

   ```python
   print("%.2f" % time.fps())
   ```

2. 启动后先预热 30 秒，不记录数据。
3. 关闭 OSD，记录随后 60 秒的 FPS 输出，计算平均值和最低值。
4. 打开 OSD，再记录 60 秒，计算平均值和最低值。
5. 测试后恢复该行为注释状态，避免改变正式版本运行开销。

若不方便导出日志，可以每隔约 5 秒人工记录一次，共记录 12 个数，再计算平均值；README 中注明采样方法即可。

## 4. 连续运行

1. 保持摄像头画面内存在至少一个可识别目标。
2. 连续运行 10 分钟，中途各切换一次队伍颜色、策略和 OSD。
3. 记录是否出现退出、卡死、花屏、模型停止输出或串口停止发送。
4. 若出现问题，记录发生时间和当时的模式，不写成“通过”。

## 5. 历史视频回放

1. 在另一块屏幕全屏播放历史调试视频，关闭播放器控件和字幕。
2. 保持 MaixCAM 与屏幕正对，避免摩尔纹和反光。
3. 对六个类别分别记录“正确”“错误”或“未覆盖”。
4. 同一类别连续出现多帧只算一个测试片段，不以帧数计算准确率。
5. 结果只能写成“历史视频回放测试”，不能写成比赛现场准确率。

## 6. 建议保留的证据

- 应用正常启动的一张照片；
- 六类目标中实际完成测试的检测截图；
- 一段包含 FPS 输出的控制台日志；
- 一段 10 分钟连续运行的起止时间记录；
- 一组完整 UART 帧的十六进制输出。
